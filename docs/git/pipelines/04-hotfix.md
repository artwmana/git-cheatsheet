Hotfix - это срочное исправление для production или основной ветки. Обычно его делают отдельно от обычной feature-разработки, чтобы быстро доставить минимальный и безопасный фикс.

Типовой сценарий hotfix
1. Переключиться на стабильную ветку `main`
2. Обновить ее
3. Создать ветку `hotfix/*`
4. Внести минимальное исправление
5. Закоммитить и отправить ветку
6. Срочно влить изменение

Пример команд
```bash
git switch main
git pull --rebase
git switch -c hotfix/login-500
git add .
git commit -m "Fix login 500 error"
git push -u origin hotfix/login-500
```

После вливания
- hotfix должен попасть в `main`
- если есть `develop` или релизные ветки, фикс надо перенести и туда
- ветку `hotfix/*` после завершения обычно удаляют

Что важно помнить
- В hotfix не стоит смешивать срочный фикс с рефакторингом
- Чем меньше diff, тем ниже риск сломать что-то еще
- Если проект тегируется по версиям, hotfix часто сопровождается новым патч-релизом
