`merge` и `rebase` решают похожую задачу: интеграцию изменений из одной ветки в другую. Но результат в истории у них разный.

Что делает merge
- Берет две линии истории и объединяет их
- Обычно создает отдельный merge commit
- Сохраняет реальную форму ветвления

Что делает rebase
- Переписывает коммиты текущей ветки поверх новой базы
- Делает историю более линейной
- Меняет SHA коммитов

Примеры
```bash
git merge main
git rebase main
```

Когда использовать merge
- Если важно сохранить реальную историю разработки
- Если ветка уже общая и переписывать историю нежелательно
- Если команда привыкла к merge commits

Когда использовать rebase
- Перед PR, чтобы подтянуть свежий `main`
- Для локальной чистки истории
- Если нужна линейная история без лишних merge commits

Что важно помнить
- Не стоит делать rebase опубликованной общей ветки без договоренности
- После rebase обычно нужен `git push --force-with-lease`
- `merge` безопаснее, `rebase` чище по истории
