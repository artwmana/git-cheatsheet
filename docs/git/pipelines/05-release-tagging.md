Теги используются для фиксации релизных точек в истории. Обычно тег ставят на коммит, который соответствует версии, опубликованной в production или отданной пользователям.

Зачем нужны теги
- быстро находить релизы
- собирать конкретную версию проекта
- сравнивать изменения между версиями

Основные команды
```bash
git tag
git tag v1.0.0
git tag -a v1.0.0 -m "Release 1.0.0"
git show v1.0.0
git push origin v1.0.0
git push --tags
```

Типовой release flow
1. Убедиться, что нужный коммит находится в `main`
2. Создать тег версии
3. Отправить тег на remote
4. При необходимости собрать changelog или release notes

Что важно помнить
- Легковесный тег проще, аннотированный тег полезнее для релизов
- Теги не отправляются обычным `git push`, если явно не указать тег или `--tags`
- Удаление и перенос уже опубликованных тегов требует аккуратности
