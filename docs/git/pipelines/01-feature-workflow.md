Feature workflow - это самый частый процесс в командной разработке. Суть в том, что каждая задача делается в отдельной ветке, затем проходит ревью и только потом попадает в основную ветку.

Базовый сценарий
1. Обновить `main`
2. Создать feature-ветку
3. Сделать изменения и коммиты
4. Отправить ветку на remote
5. Открыть Pull Request
6. После ревью влить изменения

Пример команд
```bash
git switch main
git pull --rebase
git switch -c feature/login-form
git add .
git commit -m "Add login form"
git push -u origin feature/login-form
```

После ревью
```bash
git switch main
git pull --rebase
git branch -d feature/login-form
```

Почему такой процесс удобен
- `main` остается стабильной
- задачи изолированы друг от друга
- код-ревью проще проводить по отдельным веткам
- историю изменений легче читать

Частые ошибки
- делать работу прямо в `main`
- смешивать несколько задач в одной ветке
- забывать обновлять ветку от актуального `main`
