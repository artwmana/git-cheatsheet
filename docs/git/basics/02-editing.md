Работа с изменениями - это повседневный цикл разработки. Сначала смотрим статус файлов, затем добавляем изменения в индекс, создаем коммит и синхронизируемся с удаленным репозиторием.

Основные команды цикла
- status Показывает состояние рабочего дерева и индекса
- add Добавляет изменения в staged
- commit Сохраняет staged-изменения в историю
- fetch Скачивает обновления с remote без слияния
- pull Получает изменения и сразу пытается интегрировать их
- push Отправляет локальные коммиты в удаленный репозиторий

Базовый рабочий цикл
```bash
git status
git add .
git commit -m "Add login form"
git fetch
git pull --rebase
git push
```

Типовые команды
- `git add .` добавить все изменения из текущей папки
- `git add <file>` добавить конкретный файл
- `git commit -m "message"` создать коммит с сообщением
- `git commit --amend` поправить последний коммит
- `git push -u origin <branch>` отправить ветку и связать upstream

Разница между fetch и pull
- `fetch` только скачивает новые коммиты и ссылки
- `pull` делает `fetch` и затем merge или rebase

Что важно помнить
- Без `git add` изменения не попадут в коммит
- `git pull --rebase` часто удобнее обычного `pull`, если нужна линейная история
- `git push` не работает, если локальная ветка не знает, куда пушить
