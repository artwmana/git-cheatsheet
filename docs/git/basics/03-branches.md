Ветки нужны для параллельной разработки. Обычно каждая новая задача делается в отдельной ветке, а затем изменения объединяются обратно в основную ветку.

Основные команды для веток
- branch Показывает список веток, создает или удаляет ветку
- switch Переключает рабочее дерево на другую ветку
- merge Объединяет историю одной ветки с другой

Частые команды
```bash
git branch
git switch -c feature/auth
git switch main
git merge feature/auth
git branch -d feature/auth
```

Типовые сценарии
- Создать новую ветку под задачу: `git switch -c feature/x`
- Переключиться на существующую ветку: `git switch feature/x`
- Посмотреть все локальные ветки: `git branch`
- Посмотреть локальные и удаленные ветки: `git branch -a`
- Удалить уже влитую ветку: `git branch -d feature/x`

Merge на практике
- Из основной ветки вливают feature-ветку после завершения работы
- Если истории разошлись, Git может создать merge commit
- Если конфликтов нет, объединение часто проходит автоматически

Что важно помнить
- Рабочая ветка должна иметь понятное имя: `feature/*`, `fix/*`, `hotfix/*`
- Перед merge полезно обновить основную ветку через `git pull`
- Не стоит коммитить в `main` напрямую, если команда работает через feature-ветки
